# DayGlyph v2 Stage 3 情绪宇宙设计规格

**日期：** 2026-06-18  
**范围：** Stage 3A、3B、3C 一次性交付  
**目标页面：** U-00、U-01、U-02、U-03、U-04

## 1. 目标与边界

Stage 3 将当前宇宙占位页替换为可完整演示的情绪宇宙：用户可以按月份查看由日记录聚合出的月星球，在 3D 场景或等价 2D 列表中选择日期，查看月度详情，并以月、季、年范围回顾描述性趋势和导出静态图片。

本阶段一次完成路线图中的 3A、3B、3C，但实施和提交仍按顺序拆分，以便逐步验证和回退。

本阶段不实现：

- Echo 回声、行动反馈和通知调度。
- Mine 历史、成就和设置迁移。
- 网络同步、公开分享或云端统计。
- 持久化的月星球或月统计 SwiftData 模型。
- 情绪总分、健康分、排行榜或好坏排序。

## 2. 架构决策

采用“纯聚合核心 + 双渲染器”架构。

`DayEntry` 是唯一事实来源。新增无副作用的 `UniverseAggregator`，实时把查询到的记录转换为 `MonthlyUniverseSummary`、`UniverseTrendSummary` 等不可变值类型。RealityKit 3D 场景、SwiftUI 2D 降级列表、月详情和趋势页全部消费同一组派生值，不在各 View 内重复统计。

不新增 `MonthlyPlanet` 持久化对象。这样记录新增、更新或删除后，日期光点、月统计和趋势会随 SwiftData 查询自动重算，避免缓存失效和数据迁移。

建议组件边界：

- `UniverseAggregator`：月份分组、月视觉聚合、关键词与天气分布、趋势区间计算。
- `MonthlyUniverseSummary`：月份、有效日期、日记录、稳定视觉参数和描述性摘要。
- `UniverseInteractionPolicy`：切月阈值、相邻日期、当前月定位和降级条件等纯逻辑。
- `UniverseView`：U-00/U-01 容器和页面级状态所有者。
- `UniverseRealityScene`：仅负责 RealityKit 实体构建、更新和命中测试。
- `UniverseAccessibleList`：2D、VoiceOver 和异常降级入口。
- `MonthlyPlanetDetailView`：U-02 月星球详情。
- `UniverseDaySummaryView`：U-03 日期摘要 Sheet。
- `UniverseTrendsView`：U-04 图表、表格替代和导出。

## 3. 聚合数据规则

### 3.1 月份与日期

- 以用户当前日历和时区的自然月分组。
- 每个自然日最多生成一个日期光点；若遗留数据存在同日多条记录，选 `updatedAt` 最新的一条作为该日代表。
- 月份标识使用该月第一天的本地日历起点，不使用固定秒数偏移。
- 删除记录后重新聚合，不保留光点、摘要或导航死链接。

### 3.2 月星球视觉

- `baseHue` 和 `secondaryHue` 按有效日记录的情绪权重及日星球颜色做圆周加权，避免 0/360 度平均错误。
- `textureComplexity` 来自月内日星球复杂度和情绪分布离散度，限制在 0.20–0.85。
- `glow` 来自平均唤醒度和记录完整度，限制在 0.25–0.90。
- 星球尺寸只按有效记录天数映射到 0.88–1.12 倍，不暗示情绪严重程度。
- 轨道环、卫星数和粒子密度有明确上限；低功耗降低粒子数量，减少动态时停止自动旋转。
- 稳定 seed 由年月、有效日期和各日已保存的 `PlanetVisual.seed` 组合生成。同一数据重复进入必须得到相同结果，记录变化后允许结果变化。
- 日期光点与有效日期一一对应，视觉直径可以小于 10 pt，但交互命中区至少 44 pt。

### 3.3 描述性统计

- 月、季、年范围共用同一个聚合入口和日期边界。
- 展示情绪构成、记录频率、唤醒度波动范围、天气分布和常见关键词。
- 少于 7 个有效记录日时，只展示事实数据和“至少记录 7 天后显示趋势”，不输出规律性总结。
- 所有自动摘要标明样本日期区间和有效记录日数，并使用“仅基于你的记录”。

## 4. 页面与交互

### 4.1 U-00 宇宙空状态

没有有效记录时显示深色全屏背景、低密度静态星点、半透明未形成星球、标题“你的宇宙还在等待第一颗星球”和一个主按钮。主按钮通过 `AppRootView` 的 Tab 选择绑定切回“今日”，不显示空白 RealityKit 场景。

### 4.2 U-01 月轨道宇宙总览

当前月份的主星球位于视觉中心，直径 220–280 pt；前后月星球沿轨道以 72–120 pt 远景呈现。顶部玻璃控制显示年月和“回到本月”，底部玻璃卡显示记录天数与事实摘要，并提供月详情和趋势入口。

横向拖动位移达到约 56 pt 或速度超过 380 pt/s 时切月，否则回弹。单指从主星球区域开始时旋转星球，双指缩放查看细节；这些手势不改变当前月份。重复进入宇宙 Tab 时默认定位本月，详情返回后保留月份、旋转、缩放和选中日期。

### 4.3 U-02 月星球详情

详情页上半屏展示大星球，下方展示有效记录天数、主要配色的文字解释、复杂度说明、日期光点图例、关键词、事实趋势和“查看全部日期”。只有 1 个有效记录日时显示“数据还少”，不生成变化结论。

星球区域处理旋转，文字区域处理滚动，避免手势竞争。颜色、纹理和复杂度均有文字替代，不只依赖视觉。

### 4.4 U-03 日期落点摘要

点击 3D 日期光点或 2D 日期项后，在当前宇宙背景上展示 260–330 pt 的底部玻璃摘要卡。内容包括日期、鸡尾酒名、情绪天气、关键词、日星球缩略图和“完整记录”入口。

左右切换只移动到同月相邻的有效记录日期，边界不循环。进入完整记录时复用现有 `EntryDetailView`。关闭摘要后保留当前月、旋转和缩放状态。

### 4.5 U-04 宇宙趋势与统计

使用 Swift Charts 提供月、季、年范围切换。默认展示描述性构成，不显示单一总分。每张图表同时提供可读文字和表格替代，图例按出现频率排序，筛选不能导致所有数据被隐藏。

静态导出使用 `ImageRenderer` 生成固定尺寸、包含标题、样本区间、事实数据和“仅基于你的记录”的图片，再调用系统分享面板。导出失败显示中文可恢复提示，不丢失当前筛选状态。

## 5. RealityKit 与降级策略

RealityKit 只负责视觉呈现，业务状态不存放在实体树中。场景包含主球体、最多三个内部或表面色层、轨道环、有限卫星、日期光点和低密度粒子。实体名称或组件保存稳定的月份/日期标识，命中测试后由 `UniverseView` 更新 SwiftUI 状态。

以下情况使用完整的 SwiftUI 2D 列表/表格替代：

- VoiceOver 正在运行。
- 系统开启减少动态。
- 设备处于低功耗模式时采用低细节；若场景创建失败则完全降级。
- RealityKit 初始化或资源创建失败。

2D 降级不是只读错误页。它必须支持切月、查看月摘要、选择日期、打开完整记录和进入趋势。减少动态模式允许保留静态 3D 或直接使用 2D，首要条件是所有任务可完成且没有自动旋转。

## 6. 状态、错误与可访问性

- 空数据、记录删除、导出失败和 3D 失败均显示用户可理解的中文状态，不暴露技术堆栈。
- 日期选择必须在聚合结果变化后重新校验；已删除日期立即关闭摘要或移动到仍存在的有效日期。
- 深色玻璃文字保持高对比；紫色只用于当前月和交互焦点。
- 所有控制命中区不小于 44 pt，支持大字体换行和纵向布局。
- VoiceOver 顺序为：页面标题、月份控制、月摘要、日期列表、详情/趋势操作。
- 星球的可访问性描述包括月份、记录天数、主要色彩含义和复杂度文字，不把纹理或亮度描述为情绪好坏。

## 7. 测试策略

遵循测试驱动开发，每个行为先写失败测试并确认失败原因，再实现最小代码。

单元测试覆盖：

- 跨月分组和本地日历边界。
- 同日多条记录只产生一个光点并选择最新记录。
- 同一数据的月 seed 和视觉聚合稳定。
- 色相圆周加权与视觉参数边界。
- 记录删除后的重算结果。
- 相邻有效日期、切月阈值和回到本月逻辑。
- 少于 7 天时不输出规律性总结。
- 月、季、年区间和图表/表格使用相同数据。
- 导出内容包含样本区间和数据使用说明。

集成与人工验收覆盖：

- 全量 `DayGlyphTests` 和应用构建通过。
- iPhone 17 默认字号及 375 pt 小屏无横向溢出。
- 超大字号下正文不截断，双操作自动改为纵向排列。
- 减少动态关闭自动旋转，功能仍可完整操作。
- VoiceOver 使用 2D 等价路径，无需操作 3D 实体。
- RealityKit 同一月份重复进入外观稳定，日期光点与有效日期一一对应。
- RealityKit 场景失败时自动进入可操作降级列表。
- 静态图生成和系统分享入口可用，失败提示可恢复。

## 8. 实施与提交顺序

1. **Stage 3A：** 月聚合值类型、纯函数服务、U-00、2D 月列表、U-02、U-03 和相应测试。
2. **Stage 3B：** RealityKit 月轨道场景、稳定实体、日期命中、旋转缩放、减少动态与失败降级。
3. **Stage 3C：** 月/季/年趋势、Swift Charts、表格替代、静态图导出和性能收敛。
4. **阶段验收：** 全量测试、构建、模拟器多尺寸和可访问性走查，更新顺序路线图 Stage 3 状态。

Stage 3 只有在 U-00 至 U-04 均可完成、3D 和 2D 数据一致、全量回归通过后才视为完成。
