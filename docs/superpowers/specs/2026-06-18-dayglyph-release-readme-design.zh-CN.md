# DayGlyph 接近正式版本 README 设计规格

## 目标

把仓库首页从“开发中的产品原型说明”升级为接近正式发布版本的项目主页。README 同时服务产品浏览者和工程协作者，但阅读顺序以产品价值、核心体验和视觉辨识度为先。

## 定位与语气

- 将当前版本定义为“接近正式发布的可运行版本”，并注明仍会持续迭代。
- 使用克制、可信的产品语言，不宣称已经上架 App Store，也不暗示医疗诊断、治疗或疗效。
- 不再描述宇宙、回声、我的等模块为占位功能。
- 对设备端分析能力使用准确表述：统一分析入口优先使用可用的设备端能力，不可用时保留确定性本地降级路径。

## 信息架构

1. 品牌首屏：项目名、一句话定位、版本状态、核心视觉图。
2. 产品介绍：用户问题、DayGlyph 的解决方式、核心体验闭环。
3. 四个核心模块：今日、宇宙、回声、我的。
4. 产品原则：本地优先、非医疗化、低压力、确定性与无障碍。
5. 当前版本能力：完整列出已经进入 `main` 的功能，不列计划中的未实现能力。
6. 工程实现：架构分层、技术栈、主要目录、数据流。
7. 运行与验证：环境要求、启动命令、构建及测试命令、设备端能力说明。
8. 文档入口：产品文档、设计路线图、规格和测试要求。
9. 版本边界：仍在迭代，公开社交使用本地演示数据，当前不提供医疗功能。

## 视觉策略

- 使用仓库已有的 1600×700 核心体验闭环图作为 README 首图，不引入新的二进制素材。
- 使用现有产品文档中的关键界面图组成有限的展示区，避免堆叠全部概念图。
- 图片使用相对路径和明确的简体中文替代文本，保证 GitHub 可直接渲染。

## GitHub 元信息建议

- 首选仓库名：`dayglyph`
- 备选仓库名：`dayglyph-ios`、`dayglyph-emotion-universe`
- 描述重点：iOS、本地优先、非医疗化、情绪鸡尾酒、情绪宇宙、SwiftUI。
- 仓库改名由用户在 GitHub 设置中执行；本次只提供建议，不主动改名或修改远端描述。

## 验收标准

- 新读者在 README 首屏能理解产品是什么、解决什么问题、当前是否可运行。
- 产品内容在工程内容之前，且四个一级模块与当前代码一致。
- 不再出现“宇宙、回声、我的为占位入口”等过时说明。
- 所有图片与文档相对链接指向仓库内真实文件。
- 运行要求、工程技术栈和构建命令与当前 Xcode 工程一致。
- Markdown 无占位符、无断链、无明显格式错误。
