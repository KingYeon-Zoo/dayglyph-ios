# DayGlyph 开源 README、品牌 Logo 与产品截图设计

## 目标

将仓库从开发阶段展示页整理为正式开源项目主页：移除 v1、v2、RC 等内部代号，基于当前代码准确介绍产品；重新设计可同时用于 iOS App Icon 与 GitHub README 的品牌 Logo；使用 `images/` 中的真实产品截图制作去重、裁切和拼接后的展示素材。

## 品牌定位

DayGlyph 的核心体验是：把一句难以描述的感受转化为可收藏的情绪印记，并让每天的印记在时间中形成个人宇宙。Logo 不单独强调酒杯、星球或陪伴，而以“情绪被理解并转译”为主语义。

## Logo 设计

主方向为“情绪棱镜”。图形采用 Apple 风格的克制几何与柔和渐变：

- 圆角、紧凑、适合 iOS 图标安全区的抽象印记外形。
- 内部由连续柔和曲线形成折叠关系，并通过负形形成小型星芒。
- 暖粉与珊瑚色代表当下感受，紫蓝色代表长期回顾与个人宇宙。
- 允许轻微空间层次，但避免高光玻璃拟物、复杂纹理与过量发光。
- 不使用文字、字母、杯子、星球、人物、表情脸或医疗符号。
- 先生成 1024 × 1024 主视觉，再验证 64 px 小尺寸辨识度。
- 最终输出 README 高清 Logo，并为 App Icon 生成默认、深色与着色版本。

Logo 使用内置生图能力生成。生成后只进行必要的本地尺寸适配与资源整理，不用程序化占位图替代最终图像。

## README 信息架构

README 使用简体中文，按正常开源项目组织，不再记录内部版本阶段或实施路线：

1. Logo、项目名、一句话定位与平台信息。
2. 产品预览，首先展示三张最具辨识度的真实界面。
3. 产品简介与核心体验闭环。
4. 今日、宇宙、回声、我的四个模块的真实能力。
5. 本地优先、非医疗化、低压力、可访问等产品原则。
6. 当前技术架构与目录结构。
7. Xcode、系统版本、AI 密钥与运行步骤。
8. 构建和测试命令。
9. 隐私、联网生成、共情海与非医疗产品边界。
10. 贡献方式与许可证现状。

README 必须与代码一致：当前生成链路使用豆包 Seed 2.0 Lite 生成结构化内容、Seedream 生成鸡尾酒和日星球图片；SwiftData 保存本地记录；Apple Intelligence 相关能力与诊断只按代码实际作用描述，不能继续作为唯一正式生成链路。密钥只说明如何基于模板本地配置，不提交真实凭据。

## 截图处理

原始截图保留在 `images/`，不覆盖。新建 README 专用素材目录，使用英文、稳定、URL 友好的文件名。

处理规则：

- 去除 macOS 模拟器窗口标题栏与画面外框，只保留产品界面。
- 对同一长页面的连续截图识别重叠区，裁掉重复内容后纵向拼接。
- 不改变 UI 文案、颜色或布局，不使用生成式方式重画产品截图。
- 保留足够的页面上下文，不把标题、导航或关键操作裁断。
- 首屏使用三张独立手机画面；功能介绍使用按模块拼接的长图。
- 控制文件尺寸，确保 GitHub 页面加载合理且文字仍可辨识。

计划输出四组素材：今日体验、宇宙与趋势、回声、我的与隐私。成就、情绪历史、月星球详情等作为相应模块的补充画面，不把 21 张原图全部平铺在 README 中。

- 所有相对链接与图片路径有效。
- 项目至少完成一次命令行构建验证；若环境允许，再运行相关测试。
