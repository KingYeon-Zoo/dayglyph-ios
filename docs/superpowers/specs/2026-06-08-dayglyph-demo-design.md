# DayGlyph（一划）完整演示版设计

日期：2026-06-08

## 目标

DayGlyph 的演示版要能给甲方完整展示产品闭环：用户写下当天的一段轻量记录，App 在本地理解情绪与主题，并生成一个专属 Glyph。连续多天的 Glyph 组成情绪月历，形成“我的情绪语言”的视觉记忆。

这个版本不是静态样机。它需要能真实输入、分析、生成、保存、查看月历、查看详情、设置提醒，并能通过演示数据快速呈现完整月份效果。

## 产品口径

“每天一句话”是传播口径，不是输入限制。真实体验是：用户可以写一句话、几句话，或者一小段当天感受。界面文案强调低门槛：

- 主标题：今天留下些什么？
- 输入提示：一句话也可以，一小段也很好。
- 软字数建议：280 字左右。
- 超过软建议不阻止保存，只提示“可以更轻一点”。

## 范围

演示版包含以下功能：

1. 今日记录输入。
2. 本地情绪、能量、主题词分析。
3. SwiftUI Canvas Glyph 生成。
4. SwiftData 本地保存每日记录。
5. 当天重复生成时更新当天记录。
6. 月历视图展示当前月份所有 Glyph。
7. 日期详情页展示原文、情绪、主题词、能量值和大 Glyph。
8. 设置页管理每日提醒时间与通知权限。
9. 一键填充最近约 30 天演示数据。
10. 一键清空数据，便于重复演示。

不在第一版演示范围内：

- iCloud 同步。
- 社交分享。
- 复杂统计报表。
- 账号系统。
- 云端图像生成。

## 技术原则

1. 本地优先：记录、分析和 Glyph 生成默认在本机完成。
2. 演示稳定：Foundation Models 作为可插拔分析能力，不阻塞 Demo 编译和演示。
3. 视觉可解释：Glyph 不是随机图片，而是由情绪、能量、主题和日期种子共同决定。
4. 结构清晰：分析、数据、渲染、提醒、演示数据分模块实现。

## 核心模块

### `DayEntry`

SwiftData 模型，替换模板里的 `Item`。

字段：

- `date: Date`
- `text: String`
- `emotionRawValue: String`
- `energy: Double`
- `theme: String`
- `keywordsBlob: String`
- `glyphSeed: Int`
- `createdAt: Date`
- `updatedAt: Date`
- `isDemo: Bool`

同一天只保留一条主记录。保存今日记录时，如果当天已有记录，则更新原记录。

### `EmotionAnalyzer`

本地分析服务。输入用户文本，输出 `EmotionAnalysis`：

- 主情绪：平静、喜悦、低落、焦虑、激动、疲惫、感恩、混合。
- 能量值：0.0 到 1.0。
- 主题词：工作、关系、成长、休息、家庭、健康、创造、未知。
- 关键词：从文本中提取 1 到 4 个可展示词。

第一版用规则分析保证稳定：

- 情绪关键词加权。
- 标点和语气强度影响能量值。
- 文本长度影响轻微能量修正。
- 中英文关键词都支持基础识别。

后续如果 Foundation Models API 在本机 SDK 中可稳定编译，则让 `EmotionAnalyzer` 内部优先调用 Foundation Models，失败时回退到规则分析。UI 不直接依赖具体分析实现。

### `GlyphSignature`

把分析结果转成可渲染的视觉参数：

- 色板：由情绪决定主色、辅色、背景色。
- 结构：由情绪决定圆弧、放射、折线、点阵或混合。
- 密度：由能量值决定线条数量、笔触强度和旋转变化。
- 稳定性：由日期、情绪和文本生成 `glyphSeed`，同一天同记录稳定复现。

### `GlyphCanvasView`

SwiftUI Canvas 渲染 Glyph。

规则：

- 今日页和详情页使用大尺寸 Glyph。
- 月历页使用同一算法的小尺寸缩略图。
- 所有 Glyph 都可在不同尺寸下稳定缩放。
- 不依赖网络和图片资源。

### `ReminderService`

负责：

- 请求本地通知权限。
- 保存提醒开关和提醒时间。
- 注册每日重复提醒。
- 取消提醒。

提醒文案：

- 标题：今天的一划
- 内容：留一点今天给自己。

### `DemoDataSeeder`

负责生成最近 30 天左右的演示记录。

要求：

- 文案覆盖不同情绪和主题。
- 每条数据有稳定日期和 Glyph。
- 不覆盖用户非演示数据，除非用户选择清空全部记录。
- 设置页提供“填充演示月”和“清空全部记录”。

## 界面结构

### App 外壳

使用 `TabView`：

1. 今日
2. 月历
3. 设置

每个 Tab 内部使用 SwiftUI 原生导航。

### 今日页

主要内容：

- App 名称“一划”和日期。
- 标题“今天留下些什么？”
- 多行输入框。
- 字数提示。
- “生成今日一划”按钮。
- 生成后的 Glyph 结果卡片。
- 情绪、主题、能量标签。

交互：

- 空文本时按钮禁用。
- 输入后点击按钮，执行分析、生成并保存。
- 保存成功后展示结果。
- 如果今天已有记录，进入页面时显示已有结果，用户可以继续编辑并重新生成。

### 月历页

主要内容：

- 当前月份标题。
- 上月/下月切换。
- 7 列日期网格。
- 每个有记录日期展示 Glyph 缩略图。
- 无记录日期展示淡色占位。

交互：

- 点击有记录日期进入详情页。
- 演示数据入口可以放在工具栏或设置页；为了避免月历页过载，主入口放设置页。

### 详情页

主要内容：

- 大 Glyph。
- 日期。
- 情绪、主题、能量。
- 原文。

交互：

- 删除当天记录。
- 删除后回到月历页。

### 设置页

主要内容：

- 每日提醒开关。
- 时间选择器。
- 通知权限状态。
- 填充演示月。
- 清空全部记录。
- 隐私说明：记录与分析保存在本机。

## 视觉方向

采用“安静仪式感”。

视觉关键词：

- 温暖浅底。
- 深墨绿色或炭黑正文。
- 情绪色少量点缀。
- Glyph 是视觉主角。
- 控件克制，避免过度游戏化或玄学化。

基础色彩方向：

- 背景：暖白、浅雾绿。
- 正文：深墨绿、炭黑。
- 平静：青绿。
- 喜悦：暖黄。
- 低落：蓝灰。
- 焦虑：紫蓝。
- 激动：珊瑚红。
- 疲惫：灰褐。
- 感恩：金橙。
- 混合：多色组合。

## 错误和边界

- 空输入：禁用生成按钮。
- 超长输入：提示更轻量，但不阻止保存。
- 通知权限拒绝：设置页显示“可在系统设置中开启通知”。
- SwiftData 读写失败：保留当前输入并显示保存失败提示。
- 演示数据重复填充：先删除旧的演示数据，再重新生成，不影响用户真实记录。

## 测试和验证

实现后需要验证：

1. 项目能编译通过。
2. 今日页空输入不能生成。
3. 输入文本后能生成并保存记录。
4. 同一天再次生成会更新记录，而不是新增重复日期。
5. 月历页能展示 Glyph 缩略图。
6. 点击月历日期能进入详情页。
7. 演示数据能填充约 30 天记录。
8. 清空数据能移除记录。
9. 提醒设置能请求权限并注册本地通知。

优先添加轻量 Swift Testing 单元测试：

- 情绪分析规则。
- Glyph 种子稳定性。
- 同日记录更新逻辑如果能抽出纯逻辑则测试。

## 演示脚本

1. 打开 App，展示今日页：“一句话也可以，一小段也很好。”
2. 输入一段当天感受。
3. 点击“生成今日一划”，展示 Glyph 和情绪分析。
4. 进入设置页，点击“填充演示月”。
5. 进入月历页，展示完整月份 Glyph。
6. 点击某一天，解释该符文背后的情绪和主题。
7. 打开提醒设置，展示每日提醒能力。

## 验收标准

甲方能在一台本地 iPhone Simulator 或真机上看到完整闭环：

- 能写。
- 能分析。
- 能生成 Glyph。
- 能保存。
- 能看月历。
- 能看详情。
- 能设置提醒。
- 能快速填充演示数据。

Demo 不依赖服务器、账号、网络或外部图像生成服务。
