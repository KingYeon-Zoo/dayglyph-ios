# DayGlyph v2 顺序实施路线图

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:writing-plans before turning any phase below into an executable implementation plan. Do not execute phases in parallel. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把产品部 2026-06-16 的 DayGlyph v2.0 正式文档拆成可逐个交付、可逐个验收的 iOS 实施阶段。

**Architecture:** 先建立 v2 数据与导航骨架，再逐个替换用户可见模块。每个阶段只产出一组可演示页面和对应测试，不把后续模块的复杂逻辑提前塞入当前阶段。

**Tech Stack:** SwiftUI、SwiftData、Swift Testing、Foundation Models 现有统一分析入口、UserNotifications、后续 Universe 阶段使用 RealityKit/RealityView。

---

## 范围判断

正式产品文档覆盖四个一级模块、二十多个页面、数据迁移、视觉系统、通知、分享、无障碍和 Demo 脚本。它不是一个可一次性执行的单计划。当前仓库仍是旧版三 Tab：`今日`、`月历`、`设置`，并且用户可见结果仍是 Glyph。因此必须按下面顺序推进。

硬约束：

- [ ] 任一阶段未通过验收前，不启动下一阶段实现。
- [ ] 任一阶段只允许修改它声明的文件范围；跨阶段依赖只能通过稳定模型、服务或组件接口暴露。
- [ ] 每个阶段完成后跑单元测试；涉及 UI 的阶段至少在 393 pt 基准宽度和 375 pt 小屏宽度人工走查。
- [ ] 所有新增用户可见文案使用简体中文，且不得出现医疗诊断、疗效承诺、惩罚性签到文案。

## 阶段 1：v2 基础架构与 Today 核心闭环

详细计划文件：`docs/superpowers/plans/2026-06-17-dayglyph-v2-foundation-and-today-core.zh-CN.md`

目标页面：

- T-00 今日空状态
- T-01 情绪记录输入
- T-02 分析与生成
- T-03 情绪鸡尾酒结果
- 四 Tab 应用壳，但 Universe/Echo/Mine 只提供稳定占位和后续入口，不实现业务闭环

交付标准：

- [ ] 底部导航从三项替换为 `今日`、`宇宙`、`回声`、`我的`。
- [ ] Today 主路径完成“记录 -> 调制 -> 鸡尾酒结果”，用户界面不再出现“一划”、`Glyph`、百分比严重度。
- [ ] 每条记录保存稳定的 `EmotionRecipe`、`CocktailVisual`、`PlanetVisual`、`MoodWeather` 派生数据或等价可复现字段。
- [ ] 旧 `glyphSeed` 只作为兼容字段，不再进入主界面。
- [ ] 现有分析服务继续作为统一入口，UI 不暴露 Foundation Models 品牌。

不做：

- [ ] 不实现完整宇宙 3D。
- [ ] 不实现微行动状态机。
- [ ] 不实现回声、时间来信、共情海。
- [ ] 不实现成就和统计。

## 总验收口径

- [ ] 90 秒演示路径能完整走通：今日记录 -> 调制 -> 鸡尾酒 -> 宇宙 -> 微行动 -> 回声 -> 共情海 -> 我的隐私。
- [ ] 旧版可见文案 `一划`、`Glyph`、`月历`、`设置` 不再作为一级体验出现。
- [ ] 默认数据本地保存，任何公开副本都经过二次确认。
- [ ] 减少动态、大字体、高对比和 VoiceOver 至少覆盖关键页面。
- [ ] Demo 数据带 `isDemo` 标识，清除演示数据不误删真实记录。
